# 更新のしかた(ふだん使う手順)

## 方法 1. AI に頼む(Issue に「@ai」)

1. リポジトリ上部の **Issues → New issue**。
2. タイトルと本文に、やってほしいことを書く。本文のどこかに **`@ai`** と入れる。写真はドラッグで貼れる。

   例:
   ```
   @ai
   10/4 に UbiComp 2026(オーストリア)で桂さんが口頭発表しました。
   タイトル: ○○○○
   著者: 桂 章皓, 菅原 徹
   お知らせと業績に追加してください。写真は下に貼ります。
   ```
3. 数分で Issue に「変更案を作りました」とコメントが付く。リンクを開く。
4. **確認する**(次の「変更案の確認のしかた」)。
5. 直してほしいところがあれば、その Issue に `@ai ○○を△△に直して` とコメントすると、新しい変更案が作られる。

## 方法 2. inbox にファイルを置く

1. リポジトリのファイル一覧で **`inbox`** フォルダを開く。
2. **Add file → Upload files** で、メモ(.txt)・写真・BibTeX(.bib)などをドラッグ。
3. 下の **Commit changes** を押す。
4. 数分で **Pull requests** タブに「AIによる変更案」ができる。

## 方法 3. 管理画面で自分で書く(AI を使わない・クレジット 0)

写真付きのお知らせなど、**内容が決まっているものはこれがいちばん早くて確実**。AI のクレジットを使いません。

### 初めてのとき(1回だけ)

管理画面には GitHub の「トークン」でログインします。作り方は [SETUP.md の「ステップ 6. 管理画面にログインできるようにする」](SETUP.md#ステップ-6-管理画面にログインできるようにする) を参照。
一度ログインすれば、同じブラウザでは次回からそのまま入れます。

### お知らせを書く

1. `https://kit-sugahara-lab.net/new/admin/` を開く(本公開後は `/admin/`)。
2. 左のメニューで **お知らせ** → 右上の **新規作成(New)**。
3. 項目を埋める:
   | 項目 | 書き方 |
   |---|---|
   | タイトル | 例: `Eurosensors 2026` / `UbiComp 2026 で1件の発表を行いました` |
   | 日付 | 学会の最終日など、記事の日付 |
   | カテゴリ | 学会発表 / 受賞 / 論文 / プレス / 研究活動 / 研究室生活 / お知らせ |
   | 記事の写真 | 一覧とページ上部に出る1枚。クリックしてパソコン・スマホから選ぶ |
   | 本文の下に並べる写真 | 2枚目以降。何枚でも選べる(タイル状に並ぶ) |
   | 本文 | です・ます調で。誰が・いつ・どこで・何をしたかを最初に |
   - 写真は自動で小さくして保存されます(スマホの写真をそのまま選んでOK)。
   - 「下書き」にチェックを入れて保存すると、サイトには出ません。
4. 右上の **保存(Save)**。2〜3 分で本番に反映される(**変更案は作られず、直接本番に出る**ので、保存前に見直す)。
5. 反映されたかは **Actions** タブの「Build & Deploy」が緑の ✓ になったかで確認。

本文の例:
```
2026年9月6日から9日にスイス・チューリッヒで開催された Eurosensors 2026 において、桂 章皓さんが発表を行いました。

- 桂 章皓「High-Sensitivity and Reliable Gas Sensor by ...」
```

### 直す・消す

- 一覧から記事を開いて書き換え → 保存。
- 消すときは記事を開いて右上の「…」→ 削除。**旧サイトから移した記事(「旧サイトの記事URL」が入っているもの)は消さない。**

### 業績・メンバー・研究設備も同じ

左のメニューの **業績 / メンバー / 研究設備** から、同じ手順で追加・修正できます。
学会発表のお知らせを書いたら、**業績** にもその発表を登録しておくと、メンバーの実績にも自動で出ます。

### どれを使う?

| やりたいこと | おすすめ |
|---|---|
| 写真付きのお知らせ、名前や数字の修正 | **管理画面**(方法 3) |
| BibTeX や論文リストからまとめて業績登録、メモから文章を作ってほしい | AI(方法 1 / 2) |

## 変更案(プルリクエスト)の確認のしかた

AI の変更案は、**マージするまで本番には出ません**。

1. リポジトリ上部の **Pull requests** を開き、「AIによる変更案」をクリック。
2. **Conversation タブ**: AI の報告と「要確認」の点が書いてある。「ビルド失敗」と出ていたらマージしない。
3. **Files changed タブ**: 追加・変更された文章が緑(追加)と赤(削除)で表示される。日付・氏名・タイトルを確認する。
   - 小さな修正なら、ファイル右上の「…」→ **Edit file** でその場で直せる。
4. **見た目を確認**: 変更案ができて数分後、プレビュー
   `https://b23151503-kit.github.io/sugahara-lab-web/`
   に変更案の内容が表示される(左下に「プレビュー表示中(ブランチ: ai/… や copilot/…)」)。変更案が更新されるたびに自動で表示し直す。
   - Copilot の変更案で、PR 画面に **Approve and run workflows** というボタンが出ていたら押す(押すとプレビューが動く)。
   - それでも表示されないときは **Actions → PR preview → Run workflow** で、欄に変更案のブランチ名を入れて実行。
     ブランチ名は PR のタイトルではなく、タイトルの下の「… into main from ○○」の **○○(青い文字)** の部分。
   - Issue に貼った画像は、このとき自動でサイト内(`public/uploads/`)に保存される。
5. 問題なければ Conversation タブ下の **Merge pull request → Confirm merge**。2〜3 分でサーバーに反映される。
6. やめるときは **Close pull request**。

## 反映されたかの確認

**Actions** タブで「Build & Deploy」の一番上が緑の ✓ なら反映済み。赤の ✗ なら、クリックしてエラーを確認する。
